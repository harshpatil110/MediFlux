# Task 16 Specification: Hash-Chained Audit Ledger and Audit Agent

## 1. Overview & Objective

Task 16 implements the **Tamper-Evident Hash-Chained Audit Ledger Service and Audit Agent** (RFP 3.1) for the MediFlux pharmaceutical supply chain ecosystem:
1. **Cryptographic Hash Chain (`app/core/audit_ledger.py`)**:
   - Monotonic sequence ordering (`seq = 1, 2, 3, ...`).
   - SHA-256 hash chaining:
     $$\text{hash} = \text{SHA-256}(\text{prev\_hash} + \text{canonical\_json}(\text{entry}))$$
   - Genesis predecessor hash for `seq = 1`: `'0' * 64`.
   - Single-writer concurrency locking (`asyncio.Lock`) and PostgreSQL advisory locking to maintain continuous chain integrity under heavy concurrent requests.
   - Comprehensive verification algorithm (`verify_audit_chain`) that walks the entire chain from `seq = 1` and detects direct database alterations, sequence tampering, or payload mutations, pinpointing `broken_at_seq`.
2. **Audit Agent (`agents/audit_agent.py`)**:
   - `AuditAgent` inheriting from `BaseAgent`.
   - Generates plain-language compliance and business summaries for CDSCO / regulatory inspection on key sensitive operations (`HITL_DECISION_SUBMITTED`, `BATCH_QUARANTINE`, `SCHEDULE_H_OVERRIDE`, `MODULE_ACTIVATION`, `SETTLEMENT_APPROVED`).
   - **Non-blocking guarantee**: LLM router calls are bounded by a strict 2-second timeout and wrapped in exception handlers. If the LLM times out, fails, or runs offline, the audit entry is written immediately with `explanation = ""` (the cryptographic write path never blocks on an LLM).
3. **Audit REST API Endpoints (`app/api/v1/endpoints/audit.py`, `app/api/v1/audit.py`)**:
   - `GET /api/v1/audit`: Query and filter ledger records by `entity_type`, `entity_id`, `actor`, and date ranges (`start_date`, `end_date`) with pagination (`limit`, `offset`).
   - `GET /api/v1/audit/verify`: Recomputes the entire SHA-256 hash chain from genesis and reports validation status or the exact `broken_at_seq` of any tampered entry.
4. **Database Immutability Triggers (`supabase/migrations/011_audit_ledger.sql`)**:
   - PostgreSQL trigger function `prevent_audit_tampering()` attached `BEFORE UPDATE` and `BEFORE DELETE` to `audit_ledger`, raising database exceptions to forbid mutation at the engine level.

## 2. Hash Calculation & Canonical JSON Specification

Every entry is hashed over a canonical representation with sorted keys and no whitespace separators:

```python
canonical_data = {
    "action": action,
    "actor": actor,
    "entity_id": str(entity_id),
    "entity_type": entity_type,
    "explanation": explanation or "",
    "payload": payload if isinstance(payload, dict) else {"data": payload},
    "seq": seq,
    "ts": ts,
}
canonical_json = json.dumps(canonical_data, sort_keys=True, separators=(",", ":"))
raw_bytes = (prev_hash + canonical_json).encode("utf-8")
entry_hash = hashlib.sha256(raw_bytes).hexdigest()
```

## 3. Database Schema (`supabase/migrations/011_audit_ledger.sql`)

- **Table**: `public.audit_ledger`
  - `seq BIGSERIAL PRIMARY KEY`: Monotonic auto-incrementing integer.
  - `ts TIMESTAMPTZ NOT NULL DEFAULT NOW()`: ISO timestamp of record insertion.
  - `actor VARCHAR(100) NOT NULL`: Actor identity (`agent:PharmacyAgent`, `user:UUID`, `system`).
  - `action VARCHAR(100) NOT NULL`: Action name (`CREATE_ORDER`, `HITL_DECISION_SUBMITTED`, etc.).
  - `entity_type VARCHAR(100) NOT NULL`: Entity classification (`orders`, `hitl_tasks`, `modules`, `batches`).
  - `entity_id VARCHAR(255) NOT NULL`: Entity UUID or identifier.
  - `payload JSONB NOT NULL DEFAULT '{}'::jsonb`: Arbitrary structured event payload.
  - `explanation TEXT DEFAULT ''`: Plain-language explanation generated by `AuditAgent`.
  - `prev_hash VARCHAR(64) NOT NULL`: Predecessor SHA-256 hex string (`'0' * 64` for `seq=1`).
  - `hash VARCHAR(64) NOT NULL`: Computed SHA-256 hash.
- **Indexes**:
  - `idx_audit_ledger_entity ON (entity_type, entity_id)`
  - `idx_audit_ledger_actor ON (actor)`
  - `idx_audit_ledger_seq ON (seq)`
  - `idx_audit_ledger_ts ON (ts)`
- **Engine Immutability Triggers**:
  - `trg_audit_no_update` on `BEFORE UPDATE` $\rightarrow$ calls `prevent_audit_tampering()`.
  - `trg_audit_no_delete` on `BEFORE DELETE` $\rightarrow$ calls `prevent_audit_tampering()`.

## 4. REST API Endpoints (`app/api/v1/endpoints/audit.py`)

Mounted at `/api/v1/audit` with OpenAPI tag `"Audit Ledger"`:

1. `GET /api/v1/audit`
   - **Query Parameters**: `entity_type`, `entity_id`, `actor`, `start_date`, `end_date`, `limit` (default 50), `offset` (default 0).
   - **Security**: `Depends(get_current_user)`.
   - **Response**: `{ items: [...], total: int, limit: int, offset: int }`.

2. `GET /api/v1/audit/verify`
   - **Security**: `Depends(get_current_user)`.
   - **Response (Valid)**:
     ```json
     {
       "valid": true,
       "total_entries": 42,
       "message": "Audit ledger chain integrity verified successfully."
     }
     ```
   - **Response (Tampered / Invalid)**:
     ```json
     {
       "valid": false,
       "total_entries": 42,
       "broken_at_seq": 2,
       "reason": "Hash mismatch detected at seq 2. Database payload or sequence altered."
     }
     ```

## 5. Automated Unit & Integration Tests (`tests/test_audit_ledger.py`)

1. `test_sequential_hash_chain_generation`: Verifies 5 entries generate monotonically increasing sequences, accurate predecessor hash links, and clean `/audit/verify` validation.
2. `test_direct_db_tampering_detection`: Simulates direct database tampering on row `seq=2` and verifies that verification catches the breach and identifies `broken_at_seq == 2`.
3. `test_concurrent_writes_integrity`: Executes 20 simultaneous concurrent writes via `asyncio.gather`; confirms no duplicate sequence numbers, no sequence gaps, and valid cryptographic chain integrity.
4. `test_llm_failure_resilience_non_blocking`: Verifies that timeouts (>2s) or exceptions in the LLM router fall back to `explanation = ""` immediately without failing the audit ledger write or blocking the calling agent.
5. `test_cross_component_event_coverage`: Verifies full demand cascade runs, HITL decisions, module activations, and tool `write_audit` invocations correctly log into `audit_ledger`.
