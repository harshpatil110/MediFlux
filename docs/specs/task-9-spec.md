# Task 9 Specification: Synthetic Data Agent, Seed Pipeline, and POS Simulator

## 1. Overview & Objective
Task 9 establishes the foundational simulation and demonstration layer for MediFlux. It populates the pharmaceutical supply chain network with realistic, structured, idempotent synthetic demo data without requiring manual database entry. It also implements a Point of Sale (POS) traffic simulator capable of executing diverse demand patterns (`single`, `steady`, `burst`, `stockout_run`) against the `/api/v1/events/sale` ingestion endpoint, accompanied by an environmental cold-chain sensor simulator stub.

---

## 2. Key Components & Implementation Details

### 2.1 Verified Curated Fixtures (`fixtures/`)
- `fixtures/drug_schedules.json`: Contains verified medical classifications for 20 real-world pharmaceutical products under Indian regulatory guidelines (CDSCO, DPCO, NLEM). Fields: `product_name`, `sku`, `category`, `schedule_type` ("Schedule H", "Schedule G", "OTC", "Narcotic"), `requires_prescription`, `is_cold_chain`, `min_temp_celsius`, `max_temp_celsius`, `neml_ceiling_price`.
  > [!IMPORTANT]
  > Compliance Rule: Schedule classifications are strictly sourced from human-verified fixtures rather than generated by LLMs to prevent medical compliance errors.
- `fixtures/doctor_registry.json`: Curated mock records for medical practitioner registration verification. Fields: `doctor_id`, `license_number`, `name`, `specialization`, `valid_until`.

### 2.2 Synthetic Data Generator Agent (`app/agents/seed_agent.py`)
- **Topology Hierarchy**:
  - 2 Manufacturers: *Alpha Pharma Mfg* (Baddi, North), *Apex Bio Labs* (Sanand, West).
  - 3 Regional Distributors: *Metro Logistics Hub* (North), *West Coast Depot* (West), *South Regional Hub* (South).
  - 5 Stockists / Wholesalers: Delhi Central, Mumbai West, Bengaluru South, Kolkata East, Ahmedabad Central.
  - 15 Retail Pharmacies: 3 retail pharmacies per stockist cluster across North, West, South, and East regions.
- **Related Supply Chain Assets**:
  - Products: 20 products directly mapped to `drug_schedules.json`.
  - Batches: 40 active batches (2 per product) with valid manufacturing and future expiration dates (6–24 months).
  - Inventory: 425 stock allocations parameterized by tier (pharmacies: ~80 units, stockists: ~800 units, distributors: ~5,000 units, manufacturers: ~20,000 units).
  - Credit Accounts: 25 accounts with credit limits, used credit, and credit scores (740–890).
  - Fleet Vehicles: 6 vehicles across distributors, including refrigerated reefer vans (2.0°C–8.0°C) and ambient freight trucks.
  - Production Lines & API Stock: 4 manufacturing lines (tablets, capsules, vials) and 8 API bulk stocks.
- **Deterministic ID Generation & Idempotency**: All records use UUIDv5 with a fixed DNS namespace, allowing safe and repeated upserts without row duplication.
- **Synthetic Flagging**: 100% of generated records feature `metadata: {"is_synthetic": true}`.

### 2.3 CLI Seeder Script (`scripts/seed.py`)
- Executable via `python -m scripts.seed` or `python scripts/seed.py`.
- Supports `--dry-run` to preview generation counts without writing to database.
- Idempotently populates both Supabase (when connected) and in-memory caches.

### 2.4 POS Simulator Engine (`app/simulator/pos_simulator.py` & `scripts/simulate.py`)
- **Simulation Modes**:
  - `single`: Emits 1 single `SaleEvent` for a selected pharmacy and product.
  - `steady`: Generates random sales across active pharmacies at a configurable background rate (e.g., 2 sales/sec) for a defined duration.
  - `burst`: Simulates a sudden demand spike (e.g., 50 sales in 5 seconds) for a specific product or region.
  - `stockout_run`: Targets a specific high-demand product at a single pharmacy, emitting continuous sales until inventory drops below the safety stock threshold.
- Emits structured `SaleEvent` payloads with realistic timestamps, quantity, pharmacy `node_id`, `product_id`, `batch_id`, and `correlation_id` to `/api/v1/events/sale`.
- **CLI Runner**: `python -m scripts.simulate` accepting `--mode`, `--pharmacy-id`, `--product-id`, `--rate`, `--duration`, `--region`, `--intensity`.

### 2.5 Simulator Admin API Control (`app/api/v1/endpoints/simulator.py`)
- `POST /api/v1/simulator/run`: Starts background `asyncio.Task` running `POSSimulator`. Returns `{"status": "started", "simulation_id": "...", "mode": "..."}`.
- `POST /api/v1/simulator/stop`: Cancels active background simulation tasks. Returns `{"status": "stopped"}`.
- `GET /api/v1/simulator/status`: Returns simulation telemetry (status, mode, events sent, errors, last event time).

### 2.6 Environmental Sensor Simulator Stub (`app/simulator/sensor_simulator.py`)
- Provides `SensorSimulator` interface for cold-chain telemetry simulation (`emit_telemetry(vehicle_id, temp_celsius)`), broadcasting to `coldchain.telemetry` topic on `in_process_event_bus`.

## 3. Verification & Test Suite (`tests/test_seed_and_simulator.py`)
- **Seed Pipeline Idempotency**: Executes seed routine twice sequentially; asserts exact equality of counts across all entities.
- **Synthetic Data Label Check**: Queries generated records across all 8 tables and confirms 100% contain `is_synthetic: true`.
- **Medical Schedule Integrity Check**: Confirms product catalog accurately matches classification, temperature ranges, and DPCO ceiling prices from `drug_schedules.json`.
- **Doctor Registry Integrity**: Verifies doctor mock records and licensing fields.
- **POS Simulator Single Mode**: Emits single sale event and verifies inventory decrement.
- **POS Simulator Stockout Run**: Emits sequential sales until inventory reaches safety stock threshold.
- **Simulator Admin API**: Validates `POST /run`, `GET /status`, and `POST /stop` endpoints over HTTP.
- **Environmental Sensor Stub**: Validates sensor telemetry publication on Event Bus.
