# Task M6 Specification: Sovereign Prescription Scanner & Schedule H Compliance

## 1. Overview
Task M6 delivers an end-to-end mobile Sovereign Prescription Scanner and CDSCO Schedule H Compliance workflow (`mobile/app/(tabs)/scan-rx.tsx` and `mobile/app/prescriptions/[id].tsx`) for retail pharmacy operators. It enables pharmacists to capture or pick prescription images (or select from 5 synthetic demo fixtures), compress/resize images locally, track a 4-stage sovereign LangGraph compliance pipeline (`parsing` → `schedule_check` → `doctor_verification` → `decision`) executing strictly on local models (`sensitivity="sensitive"`), view privacy-minimized results (`patient_initials` only), handle unlisted drug schedules safely (`"unknown"`, never guessed), route flagged prescriptions directly to Task M5 HITL Approvals, attach approved prescriptions to Schedule H sales in Task M4 POS Lite (`mobile/app/(tabs)/sell.tsx`), inspect RLS-scoped pharmacy history, and guarantee ephemeral device image cache cleanup immediately upon upload completion or screen unmount.

## 2. Technical Architecture & Endpoints

### 2.1 Backend Sovereign Prescription Pipeline (`backend/app/graphs/prescription.py` & `backend/app/api/v1/endpoints/prescriptions.py`)
1. **Multipart Upload & Synthetic Fixtures (`POST /api/v1/prescriptions`):**
   - Supports `multipart/form-data` uploads (`file: UploadFile`, optional `fixture_hint`, optional `node_id`) and synthetic demo triggers.
   - Executes the sovereign LangGraph workflow with `sensitivity="sensitive"`. If sensitive routing is invoked without a configured local Ollama instance, raises `SensitiveDataRoutingError` to strictly prevent cloud leakage of medical data.
   - Redacts patient names to privacy-minimized initials (`patient_initials`).
   - Normalizes doctor verification via NMC registry checks; rejects prescriptions missing registration numbers (`missing_reg_no.png`).
   - Detects CDSCO drug schedules: classifies known items (`Amoxicillin` as Schedule H, `Paracetamol` as OTC) and marks unlisted drugs (`MiracleCure`) as `"unknown"` without hallucinating or guessing.
   - When a doctor is unverified (`unknown_doctor.png`) or a drug schedule is `"unknown"` (`unlisted_drug.png`):
     - Sets `decision="flag"`, `status="flagged"`.
     - Automatically creates a pending HITL task in `public.hitl_tasks` (`task_type in ("doctor_verification", "schedule_h_override")`, linking `hitl_task_id`).
     - Emits `hitl.created` SSE events on `in_process_event_bus` for immediate pickup in Task M5 Approvals.
   - Publishes `prescription.progress` and `prescription.completed` SSE events.
   - Returns structured 4-stage pipeline `steps`, `doctor_verification_reason`, `compliance_log_id`, and `privacy_notice`.

2. **RLS-Scoped History & Prescription Details (`GET /api/v1/prescriptions`, `GET /api/v1/prescriptions/{id}`):**
   - `GET /api/v1/prescriptions`: Filters prescription records by the caller's node (`node_id`) for pharmacy roles; allows full access for `admin` and `regulator`.
   - `GET /api/v1/prescriptions/{id}`: Returns complete prescription details including steps and compliance log references; raises HTTP 403 Forbidden if a pharmacy attempts to view another pharmacy's prescription.
   - `GET /api/v1/prescriptions/fixtures`: Returns the 5 synthetic demo presets (`valid_prescription.png`, `schedule_h_prescription.png`, `unknown_doctor.png`, `missing_reg_no.png`, `unlisted_drug.png`) with data URIs for 1-tap testing in web/emulators.

3. **Schedule H POS Sale Linking (`POST /api/v1/events/sale` & `backend/app/api/v1/endpoints/events.py`):**
   - Accepts `prescription_id` in sale payload.
   - Validates that the attached prescription is approved and verified.
   - Clears Schedule H compliance holds (`compliance_hold: false`, `compliance_status: "VERIFIED_COMPLIANT"`), allowing the sale cascade to complete successfully without pausing.
   - Sales of Schedule H drugs without an approved prescription trigger `compliance_hold: true` and `compliance_status: "FLAGGED_FOR_REVIEW"`.

## 3. Mobile Screens & Components (`mobile/`)

### 3.1 Ephemeral Image Cache Cleanup (`mobile/src/features/prescriptions/imageCleanup.ts`)
- Implements strict zero-persistence privacy management:
  - `trackedTempImageUris`: In-memory set tracking all temporary file URIs generated by camera, gallery, image manipulator, or fixture staging.
  - `registerTempPrescriptionUri(uri)`: Adds URI to the tracker.
  - `cleanupPrescriptionUri(uri)`: Asynchronously deletes file via `FileSystem.deleteAsync(uri, { idempotent: true })` and unregisters it.
  - `cleanupAllTempPrescriptionImages()`: Deletes all tracked URIs, clears the registry, and returns deleted paths.
  - `getRemainingTempPrescriptionUris()`: Verifies that zero temporary files remain (`length === 0`).
- Triggered automatically:
  1. In `finally` block of prescription upload (succeeded or failed).
  2. On "Retake / Discard Photo" action.
  3. On screen unmount / exit via React `useEffect` cleanup hook.

### 3.2 Prescription Capture Card (`mobile/src/features/prescriptions/PrescriptionCaptureCard.tsx`)
- Three input modalities:
  1. **Photograph Prescription (Camera)**: Requests camera permissions; displays clear settings banner if denied; launches camera at 0.85 quality.
  2. **Choose from Gallery**: Requests media library permissions and launches picker.
  3. **Load Synthetic Demo Prescription**: 5 quick-load chips for instant fixture testing.
- Local compression via `expo-image-manipulator` (`width: 1200`, `compress: 0.75`).
- Image preview card with size badge, "Retake / Discard Photo", and "Upload & Verify Prescription".
- Upload progress bar (0% → 100%) and 4-stage active step indicator.

### 3.3 Prescription Result Card (`mobile/src/features/prescriptions/PrescriptionResultCard.tsx`)
- Status banners adhering to Warm Editorial Minimalism:
  - **Approved**: Emerald banner (`✓ Approved for Dispensing`).
  - **Flagged**: Amber banner (`⏸ Sent for Human Approval (HITL)`) with button linking to `/approvals/${hitl_task_id}` or `/(tabs)/approvals`.
  - **Rejected**: Coral Red banner (`✕ Dispense Rejected`) with compliance reason.
- Minimal data presentation:
  - Patient initials badge (e.g. `H.P.` — never full name).
  - Doctor name and NMC registration number with verification status.
  - CDSCO drug schedule badges (`OTC`, `H`, and `UNKNOWN SCHEDULE (NOT GUESSED)`).
  - Monospace compliance log ID.
  - Sovereign privacy notice.
  - Primary CTA: **"💊 Attach to Sale in POS (M4) →"** navigating to `/(tabs)/sell` with prescription parameters.

### 3.4 Screens & POS Integration
- `mobile/app/(tabs)/scan-rx.tsx`:
  - Segmented toggle: `Scan Rx` and `History (N)`.
  - Role guard restricting scanner to authorized pharmacy personnel.
  - RLS-scoped pharmacy history list with pull-to-refresh.
- `mobile/app/prescriptions/[id].tsx`:
  - Standalone prescription audit view.
- `mobile/app/(tabs)/sell.tsx`:
  - Receives `prescription_id` via route parameters.
  - Displays Emerald "✓ APPROVED PRESCRIPTION ATTACHED" badge.
  - Clears Schedule H compliance warning and submits `prescription_id` with `POST /api/v1/events/sale`.
