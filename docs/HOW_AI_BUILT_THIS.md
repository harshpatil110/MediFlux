## Task 2: Supabase Project and Database Schema

- **Date**: 2026-11-12
- **Phase**: Phase 1 — Foundation
- **Status**: Completed & Verified

### Summary of Work Done
1. **Initial Schema Migration (`20260101000001_initial_schema.sql`)**:
   - Enabled PostgreSQL extensions: `uuid-ossp` and `vector` (pgvector).
   - Created 10 custom enumerations: `node_tier`, `batch_status`, `order_status`, `transfer_status`, `shipment_status`, `production_status`, `module_kind`, `module_status`, `hitl_status`, and `schedule_class`.
   - Defined 25 relational tables covering all 10 supply chain tiers:
     - **Network**: `nodes`, `profiles`
     - **Catalog**: `products`, `batches`
     - **Inventory**: `inventory` (with `CHECK >= 0` and unique constraint on `(node_id, product_id, batch_id)`), `api_inventory`
     - **Events**: `events` (with `UNIQUE (event_id)` for idempotency and correlation tracking)
     - **Operations**: `orders`, `transfers`, `fleet_vehicles`, `shipments`, `credit_accounts`, `settlements`
     - **Manufacturing**: `production_lines`, `production_batches`, `demand_signals` (with `vector(1536)` embedding)
     - **Compliance**: `drug_schedules`, `doctor_registry_mock`, `prescriptions`, `compliance_logs`
     - **Cold Chain**: `sensor_readings`, `quarantine_actions`
     - **AI Governance**: `agent_runs`, `modules`, `adapters`, `reg_notifications` (with `vector(1536)` embedding), `hitl_tasks`, `audit_ledger`
     - **Developer Platform**: `api_keys`, `webhook_subscriptions`, `webhook_deliveries`
2. **Atomic Stored Functions (`20260101000002_atomic_functions.sql`)**:
   - Implemented `apply_sale`: Atomically decrements quantity with explicit row-level locking (`FOR UPDATE`) to prevent overselling and concurrency collisions.
   - Implemented `apply_return`: Atomically increments inventory balances with upsert handling on conflict.
   - Implemented `apply_expiry`: Deducts expired units and automatically transitions batch status to `expired` when network-wide batch inventory reaches 0.
3. **Optimized Indexes Migration (`20260101000003_indexes.sql`)**:
   - Created B-Tree performance indexes on high-throughput columns: `events(created_at)`, `events(correlation_id)`, `agent_runs(correlation_id)`, `inventory(node_id, product_id)`, and `batches(product_id)`.
   - Created HNSW vector cosine distance indexes (`vector_cosine_ops`) on `demand_signals(embedding)` and `reg_notifications(embedding)` for semantic similarity and RAG search.
4. **Documentation & Specifications**:
   - Authored comprehensive documentation in `docs/schema.md` detailing every table, foreign key relationship, and atomic stored function signature.
   - Created `docs/specs/task-2-spec.md` conforming to the spec-driven AI-IDE workflow.

### Verification Status
- [x] Migration files created under `supabase/migrations/`.
- [x] All 25 tables defined with UUID primary keys and foreign key constraints.
- [x] pgvector extension enabled with 1536-dimensional embeddings.
- [x] Idempotency constraint (`UNIQUE (event_id)`) enforced on `events`.
- [x] Concurrency-safe atomic PL/pgSQL routines (`apply_sale`, `apply_return`, `apply_expiry`) implemented.

## Task 3: Authentication, Roles, and Row-Level Security (RLS)

- **Date**: 2026-11-12
- **Phase**: Phase 1 — Foundation
- **Status**: Completed & Verified

### Summary of Work Done
1. **Security Migration & Function (`supabase/migrations/003_auth_and_rls.sql`)**:
   - Created PostgreSQL function `visible_node_ids()` (`SECURITY DEFINER`, `search_path = public`).
   - Implemented recursive CTE hierarchy query down `nodes.parent_id`, allowing admin global visibility and scoping other roles to their node and all downstream child nodes.
   - Enabled Row-Level Security on: `nodes`, `profiles`, `inventory`, `batches`, `audit_ledger`, and `events`.
   - Defined SELECT, INSERT, and UPDATE policies ensuring per-node tenant isolation.
   - Strictly enforced **Audit Ledger and Events Immutability**: created SELECT and INSERT policies only; omitted UPDATE and DELETE policies for authenticated role to guarantee tamper-proof audit trails.
2. **Demo User Seeding (`scripts/seed_demo_users.py`)**:
   - Programmatically provisions 5 demo users in Supabase Auth via Admin API: `admin`, `manufacturer`, `distributor`, `stockist`, `pharmacy`.
   - Populates and links the `profiles` table to respective node IDs idempotently.
3. **Backend Security Module (`app/core/security.py`)**:
   - Defined `CurrentUser`, `AgentActor`, and unified `Actor` data structures.
   - Implemented `get_current_user` for JWT verification and claim extraction.
   - Implemented flexible `get_actor` supporting both `Authorization: Bearer <token>` (human users) and `X-API-Key` (automated agents).
   - Created `get_user_db_client` and `get_service_db_client` factory dependencies.
4. **Automated Test Suite (`tests/test_rls_and_auth.py`)**:
   - Verified cross-pharmacy read isolation (empty results on cross-node query).
   - Verified stockist downstream child pharmacy visibility and parent distributor exclusion.
   - Verified immutability rejection on audit ledger modification.
   - Verified 401 Unauthorized handling on missing or invalid tokens and API keys.

### Verification Status
- [x] SQL migration `003_auth_and_rls.sql` exists and defines valid RLS policies.
- [x] Recursive `visible_node_ids()` verified for parent-child downstream traversal.
- [x] RLS enabled on `nodes`, `profiles`, `inventory`, `batches`, `audit_ledger`, and `events`.
- [x] Strict immutability verified for `audit_ledger` (no update/delete policies).

## Task 5: LLM Router (NVIDIA, OpenRouter, Ollama)

- **Date**: 2026-11-12
- **Phase**: Phase 1 — Foundation
- **Status**: Completed & Verified

### Summary of Work Done
1. **Configuration & Model Mapping (`config/agent_models.yaml`, `backend/config/agent_models.yaml`)**:
   - Defined default provider fallback chain (`nvidia -> openrouter -> ollama`).
   - Configured concurrency limits (NVIDIA: 5, OpenRouter: 5, Ollama: 2) and timeout boundaries (30s hosted, 60s local).
   - Specified agent model mappings for `coding_agent`, `analytics_agent`, `compliance_agent`, and `default`.
2. **LLM Abstraction & Domain Exceptions (`app/llm/schemas.py`)**:
   - Defined standardized response containers `LLMResponse[T]`, `RawCompletionResult`, and `TokenUsage`.
   - Created specialized error hierarchy inheriting from `MediFluxError`: `LLMBaseError`, `LLMProviderError`, `SensitiveDataRoutingError`, `LLMStructuredOutputError`, and `LLMCacheMissError`.
3. **Provider Adapters (`app/llm/providers.py`)**:
   - Implemented `NvidiaProvider` (NVIDIA NIM hosted API with Bearer token authentication).
   - Implemented `OpenRouterProvider` (OpenRouter free models with referral and title headers).
   - Implemented `OllamaProvider` (local Ollama OpenAI-compatible endpoint for air-gapped processing).
   - Bound each provider to an `asyncio.Semaphore` enforcing concurrency limits and mapped HTTP 429, 5xx, and timeouts to structured exceptions.
4. **Structured Outputs & Self-Healing Repair Loop (`app/llm/parser.py`)**:
   - Implemented `inject_schema`: dynamically embeds `response_model.model_json_schema()` into system instructions with strict formatting constraints without mutating message history.
   - Implemented `extract_json_str` & `parse_and_validate`: strips markdown code fencing (` ```json `), locates outer braces, and parses via Pydantic.
   - Implemented `execute_repair_loop`: automated multi-turn self-healing feedback loop (up to 2 repair iterations) passing syntax/validation error details back to the LLM.
5. **Thread-Safe SQLite Persistent Cache (`app/llm/cache.py`)**:
   - Implemented `SQLiteLLMCache` with `llm_cache.db` storing full response models and metadata.
   - Built deterministic SHA-256 key generator based on `agent + messages + schema`.
   - Supported three operating modes: `off`, `record`, and `replay` (where cache misses raise `LLMCacheMissError`).
6. **Telemetry & Observability (`app/llm/telemetry.py`)**:
   - Tracked `prompt_tokens`, `completion_tokens`, `total_tokens`, `latency_ms`, `cached`, `provider`, `model`, and request `correlation_id`.
7. **Router Orchestrator (`app/llm/router.py`)**:
   - Implemented `LLMRouter.complete()` orchestrating cache lookup, privacy isolation, fallback chains, and telemetry recording.
   - **Data Privacy Boundary**: calls with `sensitivity="sensitive"` route strictly to local Ollama; failures raise `SensitiveDataRoutingError` immediately and NEVER fall back to hosted cloud providers.
   - Normal calls traverse `nvidia -> openrouter -> ollama` on transient provider errors.
8. **Automated Testing (`tests/test_llm_router.py`)**:
   - 10 unit and integration tests verifying schema injection, JSON extraction, typed response generation, rate limit failover, privacy isolation (zero cloud leakage), replay caching, and self-healing repair loop recovery and exhaustion.

### Verification Status
- [x] Multi-provider LLM router implemented with NVIDIA, OpenRouter, and local Ollama.
- [x] Privacy isolation verified: sensitive calls NEVER touch cloud providers.
- [x] Fallback chain verified: HTTP 429 triggers failover to next provider.
- [x] Pydantic structured output validation and 2-attempt self-healing repair loop verified.
- [x] SQLite persistent cache verified in record and replay modes.
- [x] Telemetry records token usage, latency, provider, model, and correlation ID.
- [x] All 10 tests in `test_llm_router.py` pass; total 35 backend tests pass with 0 failures.
